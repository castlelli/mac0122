# Design System: MAC0122

Recorded from the built site (`src/html.c`, `SITE_CSS_LINES`, written into
`output/style.css` after the highlighter's CSS). The CSS in `html.c` is the
source of truth; this file explains it. Product facts are in `PRODUCT.md`.

## Overview

A course reference that reads like a printed catalogue: white page, black text,
one deep navy accent, thin grey rules, and system fonts. The identity is the
text itself ("MAC0122 Princípios de Desenvolvimento de Algoritmos", IME-USP,
the professor's name), never a logo or an imitation of official USP branding.
Simple and institutional: no images, no JavaScript, no dashboards, no
decoration that does not help a reader find or read something.

## Colors

### Primary

- **Navy** (`#1d3557`): the 6px rule along the top of every page, the
  "MAC0122" code in the masthead, links, the current nav item and its
  underline, table header rules, the fact table's top rule, focus outlines and
  the skip link. Nothing else.

### Neutral

- **Ink** (`#16191d`): all running text and headings.
- **Secondary ink** (`#545b64`): the institute line, nav items, labels
  ("Ordenar por:", "Chaves:"), the fact table's field names, page meta, the
  footer. About 6.9:1 on white.
- **Hairline** (`#d4d9df`): 1px rules between rows, around the nav and the key
  list, above the footer.
- **Page** (`#ffffff`): every page and the code blocks.
- **Selection** (`#d5dfeb`): text selection.

### Named Rules

- **The White Page Rule.** The page and code backgrounds are white, and the
  page declares `color-scheme: only light`, because the highlighter's colors
  were chosen for white. Dark modes must not repaint it.
- **The One Accent Rule.** Navy is the only hue in the site's own CSS. The C
  code colors (and the code block's grey border and line numbers) belong to
  the highlighter's CSS, which `style.css` includes first; they are not part
  of this palette and are not retuned here.

## Typography

One system sans stack for everything, the highlighter's mono stack for code
only. Nothing is downloaded; the site works offline.

### Hierarchy

- Course name (masthead): 1.625rem, 600; on the home page it is the `h1`.
- `h1` (index name or page title): 2rem, 700, tracking -0.015em.
- `h2` (key, section, "Índices"): 1.3125rem, 600; more space above (2.5rem)
  than below (0.75rem).
- Lead (the home page's opening sentence): 1.1875rem, line height 1.5.
- Body: 1.0625rem (1rem under 40rem), line height 1.55, prose limited to 70ch.
- Labels, nav, tables: 0.9375rem. Footer and source line: 0.875rem.
- Tables use `tabular-nums`, so dates line up.

## Layout

- One centred container, 66rem wide with 1.5rem gutters (1rem under 40rem).
- Every page: skip link, masthead, nav bar, `main`, footer.
- Footer: on the left, "MAC0122 · IME-USP" and "Construído por Alunos da
  Escola Politécnica da Universidade de São Paulo"; on the right, a "GitHub"
  link to the repository. On phones the link wraps below the credits.
- Index pages: title, "Ordenar por:" line, "Chaves:" anchor list between two
  hairlines, then one `h2` and table per key.
- Column widths are fixed per role (algorithm 22%, technique 20%, date 7.5rem,
  problem the rest) so tables line up down the page.
- Under 40rem, index tables stack: each row becomes a block with the algorithm
  in semibold and the other fields below it, each labelled from its cell's
  `data-label`; empty fields are hidden. The page never scrolls sideways.
- Under 40rem: smaller masthead and `h1`, single-column index list on the home
  page, tighter nav rows.
- Print: nav, skip link, sort and key lists hidden; links printed as text.

## Elevation & Depth

Flat. No shadows anywhere; structure comes from rules: navy for emphasis
(header rows, the top of the fact table), hairlines for separation.

## Shapes

Square. No radius in the site's own CSS; the code block keeps the
highlighter's 4px radius.

## Components

### Navigation

A row of Início and the six indexes between two hairlines. The current item is
navy, semibold, with a 3px navy underline, and carries `aria-current`: `page`
when the page is exactly that link's target, `true` when it is another sort
order of the same index. Content pages mark no item.

### Fact table (`.ficha`)

The header fields of a content page: field names in secondary ink, values in
ink, a 2px navy top rule and hairlines between rows. Only fields with a value
appear; the algorithm is the page title, so it has no row. Authors and concepts
link to their key on the index page.

### Index tables

Header row semibold over a 2px navy rule, hairline under each row, no vertical
borders. The first column is always the algorithm, linked to its page.

### Key list (`.chaves`)

The keys of an index page as a wrapped run of anchor links. Long keys (problem
sentences) are cut with an ellipsis at 24ch in this list only; the heading below
shows them whole.

### Keys and sort options

Keys appear as the TXTs spell them, accents included, with the first letter
capitalized by `::first-letter` on `h2.chave` and the key links, so every
accented letter works and the text keeps the TXT's spelling. Sort options are
written capitalized ("Algoritmo", "Técnica", "Data", "Problema"); the current
one is semibold, not a link.

## Do's and Don'ts

### Do:

- Keep every colour, size and rule in `SITE_CSS_LINES`, one literal per line,
  each under 509 characters (C89).
- Escape every TXT-derived string; build hrefs and ids with the text_utils
  writers.
- Check new pages at 1440 and 390 wide, and under forced dark mode.

### Don't:

- Don't add images, logos, web fonts, JavaScript or external requests.
- Don't put a small label or kicker above a heading; "MAC0122" stays inline
  with the course name.
- Don't add dates or run data to pages; output must stay byte-identical.
- Don't introduce a second accent colour or card-style boxes.
